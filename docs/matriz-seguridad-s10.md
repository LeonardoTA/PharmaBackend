## Entorno y precondiciones

- API principal: `http://localhost:8081/api/v1`; Swagger: `http://localhost:8081/swagger-ui/index.html`. El proyecto utiliza 8081; la colección permite cambiar `baseUrl` para usar 8080.
- T-03: segunda instancia del mismo JAR en 8082 con un secreto aleatorio distinto; rechaza el token emitido por 8081. T-04: esa instancia emite un JWT con TTL de un minuto y se espera su vencimiento real.
- Las claves se reciben por `JWT_SECRET` y la duración por `JWT_EXPIRACION_MINUTOS`. No se incluyen claves ni tokens en la colección exportada. Las capturas muestran únicamente JWT de estas cuentas locales de clase.
- C-01: se sirvió la compilación existente de la SPA desde localhost:4200, sin modificar su código. Un `fetch` con Authorization generó OPTIONS y GET; CDP registró las respuestas y se capturó la pestaña Red.
- La regla A-04 acepta mayúsculas: `findByUsernameIgnoreCase`; la creación normaliza el username a minúsculas.
- U-02 comenzó con María Huamán sin cuenta. La prueba crea `maria`; para repetir el alta 201 se necesita nuevamente esa precondición en una base de clase. Las demás cuentas conservan su estado inicial al finalizar; se restauraron contraseña y roles del vendedor.
- Los identificadores de casos solo identifican evidencias; los nombres, productos y clientes contienen datos normales. Los mensajes de error no llevan prefijos numéricos; el código HTTP permanece en el protocolo y en el campo técnico `status`.

## Orden para repetir la colección

1. Preparar Oracle con las tablas y cuentas de `src/main/resources/db/migration/V2__seguridad.sql` (script manual para una base sin estas tablas; este proyecto no tiene Flyway habilitado). Iniciar el backend con JWT_SECRET aleatorio en Base64 de al menos 48 bytes.
2. Iniciar la instancia 8082 con otra clave y JWT_EXPIRACION_MINUTOS=1. Importar la colección; sus variables token están vacías.
3. Ejecutar la preparación del token de un minuto y luego los casos en el orden exportado. Cada login guarda el JWT con Tests. Mantener el mismo tokenVendedor durante los cambios de contraseña, roles y estado.
4. Antes de T-04 esperar por lo menos 61 segundos desde su emisión. C-01 también debe repetirse desde el navegador: Postman comprueba encabezados, pero no aplica la política CORS del navegador.
5. Ejecutar la carpeta Restaurar para devolver contraseña y roles del vendedor a sus valores de clase. U-02 requiere María sin cuenta al empezar.
